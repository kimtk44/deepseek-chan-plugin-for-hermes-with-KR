# 대사 추가 가이드 (에이전트용)

대사는 **`assets/dsc-lines.json` 한 파일**에 있습니다. 이 파일을 수정한 뒤 검사기로 확인합니다. **빌드는 필요 없습니다.**

성격·말투·수위는 이 문서의 [6. 수위·톤](#6-수위톤)을 함께 참고하세요.

```powershell
node tools/check-lines.mjs
```

---

## 1. 손대는 파일

| 구분 | 파일 |
|---|---|
| 수정 가능 | `assets/dsc-lines.json` |
| 수정 금지 | `assets/dsc.js`(코드), `lib/client.js`(빌드 산출물), `plugin/*`, `pet/*` |
| 참고 | `_archive/dsc.js.bak`(분리 전 백업) |

- 새 상황 키를 만들려면 코드(`speak("...")` 호출)를 고쳐야 합니다. 대사만 담당하는 에이전트는 기존 키에 줄만 추가하세요.
- JSON 형식이 잘못되면 대사 전체가 나오지 않습니다. 코드에 폴백이 없으므로 반드시 검사기를 실행하세요.

---

## 2. 파일 구조

```json
{
  "text": {
    "hello": "첫 인사",
    "start": "작업 시작",
    "approval": "승인 대기",
    "question": "질문 대기",
    "done": "완료",
    "error": "오류"
  },
  "tools": {
    "명령 실행": "명령 실행 중…",
    "읽기": "파일 읽는 중…"
  },
  "lines": {
    "head": ["[홍조] 대사1", "[><] 대사2"],
    "chest1": ["..."]
  }
}
```

- `text`: 고정 멘트 6개를 각각 한 문장으로 씁니다.
- `tools`: 도구 상태 표시 28개입니다. 감정 표현을 빼고 **"~하는 중…"처럼 10자 안팎**으로 씁니다. 이 문구를 표시할 때는 입이 움직이지 않습니다.
- `lines`: 상황 키마다 대사 배열을 둡니다. 직전 대사는 피해서 고르므로 **키마다 3개 이상을 권장합니다.** 대사가 적으면 자주 반복됩니다.

## 4. 표정 태그

- 형식: 줄 맨 앞에 `[태그]` 또는 `[태그, 태그]`. 예: `[홍조, ><] …`
- 쓸 수 있는 태그는 **8개**입니다: `홍조` `><` `하트` `얄미운` `식은땀` `어두운` `눈물` `어지럼`
- 한 줄에 2개까지 권장합니다. 모르는 이름은 오류 없이 무시됩니다.
- 태그가 없으면 표정은 바뀌지 않습니다.

---

## 5. 문장 규칙

- **공백을 포함해 26자 이내**로 씁니다. 말풍선은 `max-width: 230px`이며 13px 글꼴로 2줄을 기준으로 합니다.
- 해요체를 씁니다. 말줄임표는 `…`(한 글자)를 쓰고 `...`(마침표 3개)는 쓰지 않습니다.
- 이모지·`ㅋㅋ`·`ㅠㅠ`·`^^`는 쓰지 않습니다. `~`, `♪`, `!`, `?`는 허용합니다.
- 같은 키 안에서 대사를 중복하지 않습니다. 다른 키와도 겹치지 않는 편이 좋습니다.
- 사용자가 답할 UI가 없으므로 **답을 기다리는 질문은 쓰지 않습니다.** 질문형을 쓰더라도 답이 없어도 어색하지 않아야 합니다.
- 사용자를 비하하거나 탓하지 않습니다. 실존 인물·정치를 언급하거나 펫이 모르는 사실을 단정하지 않습니다(작업 내용·결과 평가).

---

## 6. 수위·톤

- 목표 수위는 **NSFW 직전**입니다. 열, 숨, 떨림, 거리, 애원까지 표현하되 직접적인 행위·신체·탈의 묘사는 쓰지 않습니다.
- **꼬마 관련 키**(`body_type2`, `walk_*`, `sleep_*`)에는 성적 뉘앙스를 넣지 마세요.
- 옷을 바꾸는 방향에 주의하세요. 치마는 **켜면 길어지고**, 상의는 **켜면 가슴이 가려집니다**. 켤 때의 키는 `skirt_long`/`chest_cover`입니다.
- 캐릭터는 부끄럼이 많고 칭찬받고 싶어 합니다. 삐쳐도 금방 풀리며 사용자를 탓하지 않습니다.

## 7. 추가 절차

1. `assets/dsc-lines.json`을 엽니다.
2. 해당 키의 배열 끝에 문자열을 추가합니다. 배열 마지막 원소 뒤에 쉼표를 남기지 않도록 주의합니다.
3. `node tools/check-lines.mjs`를 실행한 결과는 **문제 없음**이어야 합니다.
4. 개발 환경에서는 새로고침합니다. 펫 창은 숨겼다가 다시 표시하면 대사를 다시 읽습니다.
5. 커밋할 때는 `assets/dsc-lines.json`을 포함합니다.

---

## 8. 자주 하는 실수

- JSON 마지막 원소 뒤 쉼표(trailing comma), 따옴표 누락, BOM
- 태그를 문장 **끝**에 붙임 → 표정 안 나옴
- 26자 초과 / `...` 사용
- 키 이름 오타 → 그 키는 **조용히 무시**됨(대사가 안 나옴)
- `text`·`tools`에 감정 섞인 긴 문장
- 검사기 없이 저장 → JSON이 깨져 대사 전체가 사라짐

---

## 9. 반영·배포

- `assets/`가 패키지에 포함되므로 JSON도 자동 포함됩니다.
- **플러그인 업데이트 시 `assets/`가 교체되어 수정본이 덮어써질 수 있습니다.** 사용자별로 대사를 보존하려면 별도 사용자 경로 라우트(2단계)를 추가해야 합니다.
- `lib/client.js`는 코드가 바뀔 때만 `npm run build`로 갱신합니다. 대사만 수정할 때는 필요 없습니다.

---

## 10. 프라이버시

- 대사 열람이 금지된 에이전트(기본 규칙상 Opus 등)에게는 **이 파일과 JSON을 넘기지 마세요.**
- 말풍선은 `textContent`로 출력되므로 HTML/스크립트를 넣어도 실행되지 않지만 데이터에는 문장만 넣으세요.
